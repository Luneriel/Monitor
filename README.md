# Monitor · 追踪计时程序

一个仅在本机运行的 Windows 桌面工具：追踪程序与网站的使用时长，并按自设规则限制使用。
开源协议：MIT（见 [LICENSE](LICENSE)）。

> **隐私说明**：所有记录只保存在本地 SQLite 文件中，不会上传到任何服务器；
> 网站追踪只读取浏览器当前标签页的 URL，不采集页面内容；键鼠钩子仅在触发「限制遮罩」期间
> 用于拦截输入，不记录任何按键内容。本工具用于本人对自有设备的使用时长自我管理，
> 不是远程监控软件。

记录指定程序 / 应用的使用时长：何时启动、何时关闭，并把每一次运行写入本地 SQLite 日志。

界面为现代化**深色**风格，布局为
**左[项目名称 + 功能栏目]、右上[窗口按钮]、右下[功能页面]**：
左侧栏为靛蓝调竖向渐变，内容区为深色画布 + 深色卡片（细边框 + 自绘柔和阴影），
靛蓝作为强调色；支持卡片悬停阴影、页面淡入淡出、滑块平滑过渡、弹窗缩放弹出等动画。

主题令牌集中在 `monitor/config.py` 的 `DARK_THEME` / `LIGHT_THEME` 两张表里，
`config.set_theme(name)` 在运行时写入这些模块级常量，随后重新应用样式表与调色板，
并**在原窗口内重建界面**（`MainWindow.rebuild_ui()`，复用同一个窗口句柄）——
不重建窗口本身，因此切换外观 / 语言时不会整窗闪烁、也不会弹出提示气泡。
语言切换同理（`monitor/i18n.py`）。

> 界面重建 / 布局上的两个坑（均已修）：
> 1. 重建后 `centralWidget()` 还没被布局撑开，读它的宽高会把导航栏压成 0 宽而"消失"，
>    因此度量一律以窗口自身尺寸为准；
> 2. 对**还没有父控件**的部件调用 `setVisible(True)` 会让它变成独立顶层窗口弹出来
>    （表现为"弹窗一闪而过"），所以一律"先 `addWidget` 入布局、再 `setVisible`"。

> 说明：UI 重构的视觉基准来自一份同需求的本地参考原型（`example/project/monitor.py`），
> 该原型**未包含在本仓库中**，此处仅说明设计来源：深色侧栏 + 靛蓝强调 + 大留白卡片。
> 后续按反馈改为深色配色，早期需求文档里的 `#FFFFFF / #F5F5F5 / #0078D7` 组合已被替代。

## 1. 运行环境

* Windows 10 / 11（x64）
* Python 3.9+（已在 Python 3.14 + PySide6 6.11 + psutil 7.2 + pywin32 312 + comtypes 1.4 上验证）
  * `comtypes` 仅用于网站追踪：通过 UI Automation 读浏览器当前标签页的网址（见"网站追踪与控制"一节）；
    没装它也不影响其它功能，只是网站识别不生效。

```powershell
git clone https://github.com/Luneriel/monitor.git
cd monitor
pip install -r requirements.txt
python main.py
```

其它启动方式：

| 命令 | 说明 |
| --- | --- |
| `python main.py` | 正常启动（显示主窗口） |
| `python main.py --silent` | 静默启动：完全隐藏主窗口、不显示任务栏图标，只留托盘图标 |
| `python main.py --windowed` | 即使设置里开着"静默启动"也强制显示主窗口 |
| `python main.py --db D:\path\monitor.db` | 指定数据库文件 |
| `python main.py --quit-after 10` | 10 秒后按正常流程退出（冒烟测试用） |
| `python main.py --selftest --shots data\shots --db data\selftest.db` | 自检：真实启动界面、走一遍主要交互、输出各页面截图与功能校验结果（**必须指定 `--db`**，否则拒绝启动） |

## 3. 需求实现对照

### 窗口与导航

* 初始窗口严格线性缩放：`宽 = 1800 × 屏幕宽 / 3840`、`高 = 1400 × 屏幕高 / 2160`；
  字体与图标保持固定像素，不参与等比缩放；之后用户可自由调整窗口大小。
* 窗口使用**自绘标题栏**（去掉系统标题栏），整体布局为
  **左[项目名称 + 功能栏目]、右上[最小化 / 最大化 / 关闭]、右下[功能页面]**：
  左侧深色栏占满整列高度（顶部是靛蓝圆角标识 + 粗体 **Monitor**），右上角一条深色横栏
  只放三个窗口按钮，其下方是页面标题栏；按住左侧空白或右上横栏可拖动窗口，双击可最大化/还原，
  窗口四角为圆角（用窗口 mask 真正裁掉四角像素，不会有残留），边缘可用系统原生方式拖拽缩放
  ——窗口最外圈 **6px** 交给系统做 `WM_NCHITTEST` 缩放，但**命中滚动条时跳过判定、把这一次点击
  让给滚动条**（最大化 / 全屏时不参与判定），所以贴边放着的滚动条照样能拖。
* 左侧导航栏宽度为窗口的 **2/9**，背景为靛蓝调竖向渐变：**首页 / 日志 / 通知 / 控制**四项以克制的
  行间距排列，分隔线以下为置底的 **设置** 与底部追踪状态（显示“正在追踪 [开启追踪的数量]/[首页程序总数] 个程序”）；当前页有选中高亮，鼠标悬停变亮。
* 右侧主内容区宽度 **7/9**：内容区画布为深色（`#0B1120`），深色卡片 / 面板浮在其上；
  顶栏以主内容区高度的 **3/35** 为基准并设舒适下限，页面标题与副标题不会贴着上沿。
  进入 / 退出"删除模式"时**就地切换卡片状态、不重建列表**（避免鼠标下的卡片被替换而闪出提示气泡）。

### 首页

* 单列纵向滚动的程序卡片：程序图标（自动从 .exe 提取，失败用默认图标）+ 名称、
  文件路径（浅灰小字）、时间信息（浅灰小字）、右侧追踪开关。
  程序与网站**分成"程序" / "网站"两个分区**显示，网站卡片用矢量地球图标区别于程序图标；
  只有一类时**不显示分区标题**，观感与以前一致。
* 名称点击后就地变成输入框：初始宽度为窗口宽度的 15%，随输入向右扩展；
  当确认按钮抵达窗口右边框后不再扩展，改为输入框下方出现水平滑块；
  右侧有"取消（灰底叉形）"和"确认（蓝底勾形）"按钮；取消 / 点击界面其他位置还原，
  确认 / 回车改名。
  > 两个按钮用 `released` 触发而不是 `clicked`，并且"点击别处即取消"的判定会在
  > 鼠标按下期间延后复查：真实鼠标点击在按下瞬间会让输入框失焦，
  > 旧逻辑会把这次点击误判成"点了别处"而先取消编辑，导致点 √ 改名无效（只有回车有效）。
* 时间信息：追踪中显示"启动时间 + 已运行 时:分:秒"，未运行显示"上次结束时间"。
* 关闭追踪开关后，卡片只保留图标、名称与开关。
* 顶部固定横栏：左侧"添加"、"删除（红底）"，中部搜索栏，右侧"排序"图标按钮。
  * 添加：按钮的**外形完全不变**，点击后弹出一个二选一下拉（"添加程序 / 添加网站"）。
    * 添加程序：调用 Windows 文件选择器（可多选）→ 弹窗（宽 50%、高 60%，超出时右侧滚动），
      每行显示图标 / 名称（可点击改名）/ 路径，底部"⊕添加其他程序"可继续追加并自动去重，
      最下方"取消 / 确认"平分宽度；确认后全部加入列表且默认开启追踪。
    * 添加网站：弹窗里是一个**多行文本框**，**每行一个域名**
      （`bilibili.com`、`*.bilibili.com`、`https://www.bilibili.com/video/*` 都行）；
      输入时底部实时提示"将添加 N 个网站 / N 个已在追踪列表中，将跳过 / N 行无效或重复，将忽略"，
      没有可添加的内容时确认按钮保持不可点；确认后逐个入库并默认开启追踪。
      已在追踪的域名与无效行不会重复写入，也不会因此报错。
  * 删除：横栏切换为左侧"全选"（全部选中后右侧出现"取消全选"）、右侧"取消 / 确认删除"；
    卡片左侧出现圆形复选框，点击卡片任意位置即可勾选，删除模式下滑块与改名被禁用；
    确认删除时弹窗提示"是否确认删除 N 个程序，该操作无法撤回"，并列出被选中的程序，
    每行右侧的滑块决定是否保留该程序日志（默认开启）。
    保留 → 从首页消失但保留日志，仍出现在日志页"按程序分类"下拉菜单；
    不保留 → 程序与日志被彻底清除。
  * 排序：按添加时间 / 名称 / 最后运行日期，均支持正序与倒序（默认按添加时间正序）；
    **手动排序**（菜单第 4 项）：选它以后，每张卡片左侧才出现**拖动手柄**，
    按住手柄即可拖动换位，顺序写入 `order.home.program` / `order.home.site`、重启后保持；
    程序与网站各自一组、不能互相拖入；这个模式下"正序 / 倒序"两项不再显示。
    动效与控制页 / 通知页完全一致（见"控制页"一节）：卡片轻微放大浮起跟随光标、
    原位留一个虚线占位框、经过的卡片让出空位、松手后落回占位框并写库。
  * 搜索：输入即刷新，支持程序名称与文件路径，命中的关键字以黄色 `#FFEB3B` 高亮。

### 进程追踪

* `psutil` 每 1 秒扫描全部进程，与追踪列表比对，检测新出现的 PID 与消失的 PID 并写日志；
  强制结束（任务管理器）同样能被捕获。
* **同一程序的多进程只记一条使用记录**（忽略重复进程）：例如微信同时开 6 个进程时，
  日志页只出现一条记录，从第一个进程出现开始、到最后一个进程结束为止；
  内部仍按 PID 分别跟踪启停时间，首页卡片显示其中**运行时间最长**的实例时长。
* 卡片右侧的追踪开关：关闭时**立即结束本次使用记录**（写入结束时间，本次时长保留在日志里），
  随后真正停止对该程序的监控（`set_programs` 会跳过 `tracking = 0` 的行，
  并且 `_scan` 在写库前会在同一把锁内再次确认该程序仍在追踪列表中——
  避免"扫描期间刚好关掉开关"的竞态又把日志重新开起来）；
  卡片第三行显示灰色"• 已关闭追踪"；开关本身是**果冻动画**（`ToggleSwitch`：350ms，
  滑块滑动时横向拉长、冲过终点再回弹，底色由灰渐变到紫，弹簧曲线 `OutBack` + 拉伸曲线
  取其正弦包络；就地更新卡片，不会重建列表，因此不会"闪一下"）。
* **重新开启追踪时本次计时从零开始**：被重新加入追踪的程序会记入 `ProcessTracker._fresh`，
  即使它已经在运行，新的一次计时也从"现在"算起（不会把关闭追踪期间的时间补进来）；
  程序启动时就已在运行的进程仍按真实创建时间计时。
* **删除动画**：在首页或日志页确认删除后，被删除的卡片 / 日志行**向右平移并淡出**
  （`QEasingCurve.InQuad`，平移速度线性提升），随后其余条目按**从上到下的顺序**依次上移
  补位（每项错开 40ms），动画结束后再按数据库结果重建列表。
* **删除动画有 2.5 秒总时长上限**（`config.ANIM_DELETE_MAX`）：单页日志最多 500 条
  （每页 200 条、单日超 200 独占一页、单日超 500 条按 500 切），逐行错开 40ms 会一路排到
  二十秒开外，而那时动画早已滚出可见范围，等于白等又白烧性能。现在错峰间隔按预算压缩
  （行越多间隔越小、可为 0），错峰本来就装得下的列表照旧；同时只给"真的要挪位置"的行挂
  动画（被删行上方那些行的目标位置就是当前位置），并挂一个上限定时器兜底 —— 万一动画真跑
  过头，没走完的行直接落到终点、立刻回调收尾，删除逻辑不会为了动画多等。
  动画期间会冻结容器尺寸（移出布局的子项否则会因布局塌陷被父控件裁剪而"整块消失"），
  并挂起列表刷新（定时刷新若重建列表会销毁正在动画的条目）——首页 `HomePage._animating`、
  日志页 `LogsPage._animating`、控制页 `ControlPage._animating`（控制页规则卡删除动画
  `slide_ratio = 0.6`，与日志页一致）。
* **删除后不会残留"幽灵卡片"**：动画会把参与动画的卡片移出布局并手工定位，
  因此 `HomePage._clear_cards()` 除了按 `self.cards` 清理，还会按控件树兜底扫掉所有
  残留在 holder 上的卡片；`on_confirm_delete()` 也不再提前清空 `self.cards`
  （否则动画结束后的 refresh 找不到旧卡片，首页会出现重复卡片 / 已删除的程序还在）。
* **鼠标滚轮滚动动画**：`SlimScrollArea.wheelEvent` 把一次滚轮的位移做成 120ms 的
  时间插值补间（`OutCubic`），从**当前实际位置**起算，连续滚动不重置也不排队；
  首页、日志、设置页共用该实现。
* 被删除（"保留日志"）的程序**可以重新添加回来**：`add_program()` 遇到同路径但已隐藏的行时
  会就地恢复该行（`visible = 1`、按参数重置追踪开关），历史日志仍挂在同一个程序上。
* 卡片与弹窗的柔和阴影由 `paintEvent` 自绘（不使用 `QGraphicsDropShadowEffect`），
  避免该特效在内容变化时缓存不失效导致的文字闪烁/跳动。

### 网站追踪与控制

网站（`monitor/site_watch.py`）与程序**共用同一张表、同一套日志、同一套控制规则**，
只是"怎么算在用"完全不同，所以追踪器里多了一个"当前正在浏览哪个网站"的来源：

* **怎么知道浏览器现在开着哪个网站**：用 **UI Automation** 读前台窗口里 Document 元素的
  `Value.Value`（`comtypes` 调 `CUIAutomation`，属性 id `UIA_ValueValuePropertyId = 30045`），
  它给出的正是**当前激活标签页**的网址。先试过"从地址栏子窗口抠文本"，现代 Edge 走不通：
  顶层窗口类 `Chrome_WidgetWin_1` 只有 `Chrome_RenderWidgetHostHWND` 与 `Intermediate D3D Window`
  两个子窗口，**地址栏已经不是独立 HWND**（`Chrome_OmniboxView` 那套早就不存在了）。
  UIA 反而更准：窗口标题写着"和另外 4 个页面"时，它只返回当前标签页的那一个网址。
* **什么算"网站"**：只有 `http(s)://` 的网址才算，于是浏览器 / 应用自己的界面会被自然排除
  （Clash Verge 的 `http://tauri.localhost/`、DeepSeek Harness 桌面端的 `dsh-app://app/`、
  `edge://` 内部页都不会被当成网站），因此**内置浏览器同样能被追踪**——只要它当前显示的是网页。
  读不到就不计时（不猜测，比如 Firefox 用的是另一套 UIA 结构）。
* **计时口径**：只有**当前活动标签页是该网站、且承载它的浏览器窗口还在显示该页面**时才计时，
  与"程序在运行"是两回事；切走标签页或关掉窗口立即结束本次记录。
  `SiteWatcher.scan()` 每秒扫一次前台窗口，同一个标签页连续使用会**沿用起始时间**
  （否则每秒都会新开一条日志）；前台切到 Monitor 自己的窗口（例如去点遮罩上的按钮）时
  会短暂沿用上一次的判定（`STICKY_S`），避免判定抖动。
  日志与程序完全同一套：网站也只在日志里占**一条**记录，切走后自动写结束时间。
* **保活：焦点离开浏览器不再撤掉遮罩**。只要"显示该页面的那个浏览器窗口"还在（没关、
  没最小化、当前标签页仍是该网站），即使焦点不在浏览器上——切到别的程序、甚至点开视频的
  **画中画**小窗——遮罩、静音与"画面停在原处"都保持，**而且这段时间照常累计使用时长**
  （用户选定的口径：保活期间计时不停，所以每日上限会照常烧）。
  实现是 `SiteWatcher` 自己记住上一次判定的页面（`_held`）：失焦时不再返回空集合，而是复用
  上一次的页面条目并标 `held=True`；每 `HOLD_VERIFY_S = 2.5s` 用 UI Automation 复查一次
  当前标签页还是不是那个网站（换标签页 / 关窗口 / 最小化立即释放）。**复查读失败不再立刻判死**：
  UIA 偶尔会返回 `None`（页面临时不可读、Chromium 正在重建文档），单次失败就当成"离开"
  会让遮罩**闪一下又回来**——现在连续 `HOLD_FAIL_MAX = 3` 次（约 7.5s）读不到才算离开，
  中途任何一次读成功就把失败计数清零。只有"窗口不可见 / 已最小化"这类**确定性**证据才立即释放。
  以前 `scan()` 只看前台窗口，焦点一离开浏览器就返回空集合，于是 `GRACE_S` 宽限期一过
  遮罩就消失——播放中的视频"点一下别的窗口就不受限了"（实测：聚焦画中画小窗就能绕过）。
* **匹配语法**：忽略协议与 `www`、支持 `*` 通配与 `*.子域`、可带路径、大小写不敏感
  （`pattern_matches`）：`bilibili.com` 命中整个站点，`live.bilibili.com` 只命中直播间，
  `https://www.bilibili.com/video/*` 只命中视频页。
* **限制效果**（控制页里与程序规则完全同一套设置：每日上限 / 连续暂停 / 时长单位）：
  达到限制时**只遮住该网站页面的内容区**——也就是去掉标签栏与工具栏以后那块真正显示网页的
  区域（窗口矩形取 UI Automation 的 `BoundingRectangle`，属性 id
  `UIA_BoundingRectanglePropertyId = 30001`，实测它与 Chromium 的
  `Chrome_RenderWidgetHostHWND` 子窗口矩形完全一致），**标签栏留着不挡**，
  所以限制期间仍然可以正常切换标签页、切到别的标签页或别的网站**立即自动解除**；
  视频开了**画中画**时，画中画小窗上再盖一层**紧凑遮罩**（小圆角 + 短文案 + 小按钮，
  见 `OverlayWindow.set_compact()`）——画中画不是"另一个网站"，它同样受限、同样会被暂停与静音。
* **画中画怎么被认出来**（`SiteWatcher._aux_windows`）：画中画小窗**没有地址栏**，UIA 读不到网址，
  所以只能按 **Win32 特征**筛：同一个浏览器**根进程**下的顶层窗口、窗口类属于 Chromium 系、
  **有 `Chrome_RenderWidgetHostHWND` 渲染子窗口**（没有 = 对话框 / 空壳宿主）、
  **没有属主窗口**（`GW_OWNER == 0`，排除工具提示与模态框）、**可见且没最小化**、
  面积明显小于页面内容区（超过 `AUX_MAX_AREA_RATIO` 的当主窗口 / 另一个全尺寸窗口排掉）、
  且**标题与页面标题对得上**（画中画标题就是视频标题，主窗口标题是"视频标题 - 个人 - Microsoft Edge"）。
  结果每 `AUX_SCAN_S` 秒缓存一次，不必每秒枚举。命中后 `ControlService` 把它拆成**独立目标**
  （`compact = True`）：`OverlayManager._site_windows()` 对紧凑目标**不做页面内容区补偿**、
  直接盖整窗，主窗口那个目标仍按窗口位移实时贴合内容区——所以主窗口与画中画**各盖一层**，
  关掉画中画那层随即销毁。
* **画中画保活：切到别的标签页后画中画照旧被遮**（`SiteWatcher._track_pip` / `_pip_sweep`）：
  画中画没有地址栏、UIA 读不到网址，所以它只在"当前页命中限制网站、`_aux_windows` 认出它"的
  那一刻可被识别；一旦当前标签页换成别的网站（不再匹配规则），原来那条页面条目会过
  `URL_MISS_GRACE_S` 确认期释放——画中画也跟着没了遮罩，于是"把视频弹成画中画、再切到别的
  标签页"就成了绕过限制的办法。现在 `SiteWatcher` 在命中规则时把每扇小窗登记进 `_pip`
  （`hwnd` → 归属 `program_id` / 页面标题 / 起始时刻），每扫一拍做一次存活复查：**窗口还在、
  可见、没最小化、标题仍对得上** → 即使当前标签页不是限制域名，也照旧把它作为该
  `program_id` 的遮挡目标下发；窗口关掉 / 最小化 / 换了视频（标题不符）才释放。
  这种条目是 **`pip_only = True`** 的：页面矩形留空、`targets` 里不追加页面项，所以
  **只有画中画被盖住**，当前标签页（用户正常在看的那一页）不会被挡；静音也只压画中画自己的
  渲染进程（`_child_renderer_pid`），不压整棵浏览器进程树——否则会把别的标签页的声音一起停掉。
* **音频：按进程树全量静音**。Chromium 的音频不由浏览器根进程播放，而是挂在共享的
  `--type=utility --utility-sub-type=audio.mojom.AudioService` 子进程上（实测：视频在响时
  WASAPI 会话属于那个子进程，不属于浏览器根进程），所以静音集合取"承载网页的进程 +
  **整个进程树**"（`_expand()`）。代价是 WASAPI 层面**无法按标签页单独静音**：静音就是
  整个浏览器的声音一起停下（这个 API 只有"按进程"这一档）。
* **暂停播放的主通道 = 系统媒体会话（SMTC，`monitor/smtc.py`）**：以前是"只要进入受限状态
  就盲按一次媒体播放/暂停键"，毛病是"按键是**开关**语义"——视频明明已经暂停，再按一下反而
  把它**放起来**；而且不管浏览器在不在播，这一下还会打到别的应用身上。现在用 `ctypes` 直接调
  **WinRT**（`RoGetActivationFactory` → `GlobalSystemMediaTransportControlsSessionManager`，
  **不引入任何第三方依赖**）：按 **AUMID** 把"被遮罩的浏览器进程"与系统里的媒体会话精确对上，
  读到权威的 `PlaybackStatus`，再调 **`TryPauseAsync()`**——它是**幂等**的，已经暂停的会话
  再调一次仍然是暂停（实测连按两次状态都是 Paused），所以"每隔一会儿再看一眼、还在播就再按
  一次"不会来回切换。轮询与按键都在**后台线程**里（`smtc.Watcher`，默认 1 秒一拍，没有目标时
  2 秒空转），界面线程只做 `arm(pids)` 与读统计，绝不阻塞界面。读不到 AUMID 的子进程用
  **进程名子串**兜底（实测 Edge 的子进程 AUMID 为空，靠这条对上会话的 `MSEdge`）。
  只有 SMTC **整条链用不了**（老系统 / 激活工厂失败）时才退回媒体键，而且**每段播放最多补按
  `PAUSE_FALLBACK_MAX = 3` 次**（它是 toggle，按多了会反跳），靠 WASAPI 判断进程树有没有在
  出声：`_sync_site_playback()` 读 `playing_pids()`，安静 `QUIET_REARM_S = 2.0s` 后重新武装，
  于是"遮罩期间视频被放起来"还能在下一拍压回去（间隔 `PAUSE_RETRY_S = 1.5s`）。去重键是
  `(窗口, 网址)`，**直接在地址栏输网址打开视频**也会重新触发。
  按用户要求**解除后不自动恢复播放**（音量仍会还原成原来的值）。
* **网站的遮罩为什么既不能挂载、也不能拦输入**（以前的两个 bug）：
  ①Chromium 把网页画在自己的合成表面上，把遮罩**挂成浏览器窗口的子窗口**以后根本看不见
  （"遮罩没显示"）；②低级钩子是按**前台窗口 PID** 判定的，而 Chromium 的渲染子窗口就属于
  浏览器根进程，一旦把根进程放进拦截集合，标签栏和 `Ctrl+Tab` 会一起被吞掉（"无法切换标签页"）。
  所以网站目标固定走**顶层遮罩 + 只盖页面内容区**，输入不再由钩子拦、页面区的点击由遮罩自己吃掉。
* **为什么静音集合与拦截集合要分开**：网站目标要**静音**承载网页的进程，但**绝不能拦它**，
  同时 `ProcessMuter.mute()` 的入参是**完整的目标集合**（不在集合里的已登记会话会被立刻还原），
  所以网站目标的静音必须并进程序目标的那一次 `mute()` 调用，不能另起一个静音管理器
  （否则两边会互相把对方的静音还原掉）。`OverlayManager` 因此增加了一个可选的
  `site_provider` 钩子，并把"静音集合"与"拦截集合"分开维护（`_effects_mute` / `_effects_block`，
  网站的 PID 只进前者）。
* **不读不可能是网页的窗口（卡顿修复）**：`read_page()` 每个前台窗口都会先过一遍
  `can_host_page()`——资源管理器（`CabinetWClass`）、桌面、任务栏这类窗口不可能有网页文档，
  而读一次它们的 UI Automation 要 **0.76~0.84 秒**（实测；浏览器窗口只要 36~75ms）。
  加了网站追踪以后，前台一切到资源管理器就会每秒白烧 0.8 秒 CPU（表现为"Monitor 变卡了"），
  所以这些窗口直接跳过。用黑名单而不是白名单：用户要求"任何窗口都算（含 App 内置浏览器）"，
  白名单会漏掉不认识的内置浏览器宿主。
* 网站与程序共用同一套限制逻辑：目标拆分、静音与拦截的下发时机、多窗口一起生效、
  UIPI 拒绝时的置顶降级都一致；区别有两个——网站的遮罩**只盖页面内容区**（不挂载、不拦输入），
  且**没有「关闭程序」按钮**（关掉浏览器不是这里要做的事）。

### 控制

左侧导航新增 **控制** 页（`monitor/ui/control_page.py` + `monitor/control.py` +
`monitor/control_service.py` + `monitor/overlay.py`）：

* **密码**：锁定态是**整页内联表单**（不再是一张卡片）：锁图标 + 标题 + 说明 + 密码框，
  回车或点框**外面右侧**那颗**箭头按钮**解锁（`_GateField` + 独立 `IconButton`，
  提示写成 `ControlGateError`）。
  错误提示**写在输入框内右侧**，出现时输入框宽度不变（提示是绝对定位画的，
  不进布局，所以不会把整页撑得跳一下），而且**一直留到用户再次敲键**才消失；
  框内这条位置窄，长文案做了简化（"密码错误次数过多，请 N 秒后再试"在框内只写
  "错误次数过多"，剩余秒数仍写在标题下方的说明里）。
  首次进入用**同一套表单的两个输入框**设置密码，箭头按钮在第一个框外面右侧，
  "密码至少 4 位"写在第一个框里、"两次输入的密码不一致"写在第二个框里
  （至少 4 位，PBKDF2-SHA256 + 随机盐存 SQLite）；
  连续错误 3 次锁定 1 分钟（锁定期内即使密码正确也不放行，无"忘记密码"）；
  两次进入控制页间隔 ≤ 设定值免重复验证。密码用于修改/删除规则、关闭控制、临时解锁。
  **离开控制页超过这个间隔**（切到首页 / 日志 / 通知或最小化后再切回来）会重新上锁，
  必须再输一次密码；间隔内回来则继续用已解锁状态，并顺延这次免验证窗口
  （`ControlPage.showEvent / hideEvent` + `ControlService.session_grace()`）。
  间隔可在**设置页「安全」卡片**里改（`离开控制页后重新验证`，单位分钟、自由输入、
  范围 0–1440，**0 = 每次进入都要密码**，默认 60 分钟，存 `control.session_grace`；
  `ControlService` 每拍读库，改完立即生效、不必重启）。
  锁定页上的"密码错误次数过多，请 N 秒后再试"由每秒 tick 重新取剩余时间，因此**倒计时逐秒递减**，
  归零后自动恢复成常规提示（以前只在进入锁定时算一次、秒数不再变化）；
  这个 tick **不看当前是不是正看着控制页**（`gate.isVisible()` 在切到别的页面后是 False，
  老写法会让秒数停在切走那一刻），切回控制页时 `_on_page_shown` 再按真实剩余时间对齐一次。
  锁定期**输入框照旧能敲**（可以把密码先改好），被禁用的只有提交 —— 箭头变灰、回车不生效也不清空输入，
  倒计时归零后直接回车即可解锁（`_apply_gate_lock` + `_submit_gate` 的锁定分支；
  归零那一拍 `_reset_gate(keep_input=True)` 不会把这段输入抹掉）。
  这个每秒 tick（以及 `ControlService.state_changed`）**只在锁定签名变化时才重置表单**：
  以前它每秒都跑一遍完整 `refresh()`，会把用户刚敲进去的密码清空、把错误提示抹掉、
  还把焦点抢回第一个输入框（`ControlPage._gate_key` + `_reset_gate`，`_sync_gate_hint` 负责写秒数）。
* **每日使用上限**：按程序设置每日总时长（数值 + 单位，可选**小时 / 分钟 / 秒**，存库统一折算成秒），
  有效使用期间累计，本地 0 点重置；
  达到上限立即用**遮罩**覆盖该程序的所有可见窗口，遮罩显示
  "今日使用额度已用完，明天 0 点后恢复" + 距次日 0 点的倒计时。
* **连续使用强制暂停**：按程序设置阈值 X 与暂停时长 Y（同样支持**小时 / 分钟 / 秒**）；连续累计达到 X 触发暂停，
  遮罩显示"连续使用时间过长，请休息 mm:ss" + 剩余暂停倒计时；暂停期间程序可继续运行，
  但不计入每日上限、不增加连续累计。累计未达 X 就退出则开始累计休息：休息 ≥ Y 时重新打开
  会把连续累计与休息清零；休息 < Y 时两者保留，再次达到 X 时本次暂停时长 = Y − 已累计休息。
  暂停到期先清零暂停标记**与连续累计**再判断是否再次触发——否则同一个 tick 里条件立刻重新成立，
  会变成"倒计时结束就再进一次暂停"，永远解不开（现在到期即真正解除，之后重新累计）。
* **指定时间段无法使用**：按程序 / 网站设置"哪些时间段不能用"，一个目标可以有多条时段，
  每条各自设起止时间与**星期几**（勾选一 / 二 / … / 日），时间粒度到分钟
  （时 `00–23`、分 `00–59` 两个下拉，选项多所以下拉自带限高滚动）。
  跨午夜的时段（如 `22:00–07:00`）表示**从前一天的 22:00 到当天的 07:00**，星期几按**开始那一天**算
  （勾周一 = 周一 22:00 到周二 07:00），行尾会标一个"次日"提示，免得以为填错了。
  时段一到立刻遮罩（文案"当前时间不允许使用" + 距本时段结束的倒计时），页面区被盖住、音频被静音；
  时段内**不计时**——和临时解锁一样，只要遮罩生效，"今日已用 / 连续已用"都停住，
  但**日志页照常记录**这段时间的使用（会写一条"进入指定时间段"的控制日志）。
  时段结束时会把**连续累计与已累计休息一起清零**，否则休息了一整晚累计值还在，
  一出时段就会立刻触发一次强制暂停。
* **临时解锁**：只能在遮罩上触发，验证密码后可选预设或自定义分钟数；
  解锁期间**整段停表**——既不累计每日使用时长，也不累计连续使用，更不会产生新的
  "达到上限 / 触发暂停"事件（以前只是"不触发遮罩"，计时照旧累计，于是连续规则每满 X 秒
  又触发一次强制暂停：用户看到的是计时反复停住、每 X 秒弹一次"强制停止"通知，却看不到
  任何遮罩，像临时解锁根本没生效）。解锁开始时连续累计清零（正处在强制暂停则连暂停一起清除），
  结束后每日累计从原值继续、连续累计从 0 重新累计，并立即重新检查、仍触发则立即重新遮罩；
  本次结束前不能延长。控制页该程序的状态行会显示**解锁剩余时间**（"临时解锁中 剩余 01:01:01"，
  与"今日已用"同格式的时:分:秒，逐秒递减）。
  弹窗里点预设分钟只填数值、不提交；密码少于 4 位时只提示"密码至少 4 位"、**不消耗校验次数**
  （以前会拿空密码去校验，点三次就触发 1 分钟锁定，看起来像"临时解锁按钮失灵"）；
  被锁定时遮罩上直接显示"密码错误次数过多，请 N 秒后再试"并暂时禁用「临时解锁」。
* **优先级**：临时解锁 > 指定时间段 > 每日使用上限 > 连续使用强制暂停
  （临时解锁可以解除时段限制，解锁期间时段遮罩也会撤掉）。
* **遮罩窗口（优先进程内挂载，失败退回顶层遮罩）**：先按 PID 枚举目标程序的可见顶层窗口，
  每个窗口一个遮罩，优先用 `QWindow.setParent`（失败退回 Win32 `SetParent` + `WS_CHILD`）
  把遮罩**挂成该窗口的子窗口**并铺满客户区：移动、缩放、最小化、还原都由系统带着走。
  但**无边框全屏游戏会拒绝被挂载**（实测"原神"：`style=0x94000000` 的 `WS_POPUP` 窗口、
  进程权限不同，`SetParent` 直接返回 `ERROR_ACCESS_DENIED`），而 Qt 的 `setParent` 即使失败
  也会把窗口挂到自己的临时父窗口上（表现为遮罩盖不住游戏、切窗口时才冒出来）。
  所以挂载失败必须立刻 `_restore_top_level()` 把窗口还原成普通顶层窗口并标记 `unmountable`，
  之后不再重试——反复 `setParent` 正是"遮罩每 2 秒闪一下"的来源。
  还有一类窗口**能挂上、却永远看不见**：带 `WS_EX_NOREDIRECTIONBITMAP`（`0x200000`）的窗口
  自己不画到重定向表面上，而是把画面交给 DirectComposition 合成——`SetParent` 会返回成功
  （`GetParent` 也对得上），但遮罩**一像素都不渲染**（实测 VS Code：`ex_style = 0x200100`，
  顶层摆放时遮罩有 4240 个像素，挂成子窗口后 0 个）。所以 `mount_into()` 动手之前先读
  `GWL_EXSTYLE`，带这一位就直接判"不可挂载"、走顶层遮罩通路——VS Code、Discord 这类基于
  Electron / Chromium 的桌面程序统一按这条走，不是针对某一个程序打补丁。顶层兜底时：
  **把遮罩插到目标窗口正上方**（`hWndInsertAfter` 取"目标窗口上面那个窗口"，因此遮罩只压在
  目标与它上面那个窗口之间，不会盖住用户切过去的其它窗口），并且判重必须用
  `GetWindow(target, GW_HWNDPREV) == 遮罩` 这种"紧贴"判断：只判"在目标之上"不够——
  Qt 每次 `show()` 都会把遮罩抬到同层最上面，于是遮罩虽然确实在目标之上，却同时盖住了
  中间所有窗口（实测表现：焦点在 Monitor 上时遮罩盖住整屏除了焦点窗口）。
  插入点的置顶性还必须与目标一致：把遮罩插到一个 TOPMOST 窗口之后，Windows 会把遮罩
  一起带进 TOPMOST 层，于是它又浮在所有普通窗口之上——**目标自己就是置顶窗时（视频的
  画中画小窗就是）也照这条办**：遮罩与它同处 TOPMOST 层、且只比它高一位，盖住的范围
  不会超过目标窗口自己盖住的范围，所以这类目标失去焦点后遮罩照常显示；只有
  `SetWindowPos` 被 UIPI 拒绝（提权目标）时才退化成"霸屏置顶 + 只看前台"。
  z 序由**每一拍同步**校验：`is_directly_above()` 只是一次 `GetWindow`，窗口没被抬走就是
  已经紧贴目标的免费 no-op（`place_above()` 开头也直接返回），所以正常路径没有额外开销；
  只有确实被抬走（被重新激活、系统重排 DWM）才重设一次，`REMOUNT_MS = 1.5s` 现在只用在
  "挂载重试"上。失败后每 `PLACE_RETRY_MS = 5s` 重试一次。目标窗口短暂消失
  （切全屏、DWM 重排、枚举抖动）时**保留 `GRACE_S = 3s` 宽限期**，超时才销毁。
  最常见的"被抬走"就是**用户点一下浏览器（它被激活就跑到遮罩上面了）**：除了每一拍，
  还加了一条**前台事件钩子**（`monitor/winhook.py`）：`SetWinEventHook(EVENT_SYSTEM_FOREGROUND)`
  在**自己的线程**上跑消息循环，前台窗口一变就**立刻**把遮罩贴回去，不用再等最多 120ms
  （这就是"重新聚焦浏览器时遮罩会闪一下"的根因）；钩子起不来（老系统 / 找不到用户 32 库）时
  静默退回纯轮询，`last_error()` 能查到原因。
* **遮罩上的鼠标（聚焦 + 拖动窗口）**：遮罩为了不抢焦点（`WindowDoesNotAcceptFocus` +
  `WA_ShowWithoutActivating`）本来会把点击"吞掉"：点在遮罩空白处既**不会激活被遮罩窗口**
  （于是没法把它的菜单栏 / 临时解锁入口拉到最前，只能手动最小化压在上面的所有窗口），
  也**抓不住它的标题栏**（窗口挪不动）。现在遮罩空白处按下左键做两件事：
  ①**立即** `SetForegroundWindow` 把被遮罩窗口激活并提到最前（被"前台锁"拒绝时先敲一下
  `ALT` 再试，最后退回 `BringWindowToTop`）；②**按住 `LONG_PRESS_MS = 200ms`**（单次
  `QTimer.singleShot`，中途松手就取消）之后进入**自研拖动**：每 `DRAG_MS = 15ms` 读一次
  物理光标位置，按"光标位移 + 目标窗口自身的 `GetWindowRect` 变化"算出新位置并用
  `SetWindowPos(SWP_NOSIZE | SWP_NOZORDER | SWP_NOACTIVATE)` 搬动窗口，同一次回调里
  用 `window_frame_rect()` 重新贴合遮罩。松手立即停（`mouseReleaseEvent`），并额外看
  `GetAsyncKeyState(VK_LBUTTON)` 兜底（在遮罩外面松开也停）；最大化的窗口先按
  `SW_RESTORE` 还原成普通尺寸再拖（按光标相对窗口的相对位置补偿，窗口不会跳走）。
  **拖动只给程序遮罩**：**网站遮罩不再参与拖动**（`_arm_drag()` 里 `if self.is_site: return`）。
  用户实测反馈这样更好——网站遮罩盖的只是页面内容区，浏览器自己的标题栏**还露在外面**，
  直接拖标题栏就能挪窗口，而在遮罩上按住拖动会跟页面里的拖拽抢手势（视频进度条、滑块）。
  **为什么不用系统原生移动循环**（以前是 `ReleaseCapture()` +
  `PostMessage(WM_NCLBUTTONDOWN, HTCAPTION)`）：那是**异步投递**，等目标窗口处理这条消息时
  左键往往已经松开，窗口于是进入了"按钮没按下"的移动循环——它会一直跟着光标飘，只有再点
  一下才停；换成 `SendMessage` 又会让 Monitor 的界面线程一直阻塞到拖动结束（用户报告的
  "拖被遮罩的窗口时明显卡"）。点「临时解锁」「关闭程序」按钮不受影响（事件先到按钮，
  只有空白处才走这条路）。
* **提权程序（以管理员身份运行的游戏）**：UIPI 会拦掉非提权进程对提权进程窗口的 z 序调整
  （实测"原神"提权启动时 `SetWindowPos` 返回 0，唯一能生效的是 `HWND_TOPMOST`），
  此时遮罩退化为**置顶显示**，并且只有目标程序自己位于前台才显示（否则置顶遮罩会把屏幕上
  所有普通窗口一起盖住）：遮罩上会提示"该程序以管理员身份运行，遮罩只能覆盖整个屏幕。
  以管理员身份重启 Monitor 即可只遮挡该程序"，控制页顶部也提供「以管理员身份重启」按钮
  （已在管理员权限下运行时该入口自动隐藏）。z 序一旦重新可用（比如重启成管理员），
  遮罩会自动撤掉置顶并隐藏提示，不需要重启。
* **输入拦截**：遮罩生效期间安装 `WH_KEYBOARD_LL` / `WH_MOUSE_LL` 低级钩子，
  前台窗口或光标下窗口属于被限制程序时吞掉按键、点击与滚轮；点在遮罩自身
  （含「临时解锁」「关闭程序」按钮）上的事件照常放行。不注入目标进程、不修改目标程序。
  低级钩子跑在 Qt 主线程上、位于**系统输入路径**中：钩子回调不返回，整台机器的鼠标键盘
  就一直被挂住，所以这里做了两层节流——钩子侧把"被限制 PID + 遮罩窗口"快照缓存
  `STATE_TTL = 0.35s`（每个输入事件只比一次时间戳）；定时同步侧把窗口枚举
  （`SCAN_MS = 200ms`）、子进程展开（`EFFECT_TTL = 2s`）与音频会话枚举
  （`ProcessMuter.ENUM_INTERVAL = 3s`，集合变化时才 force）都做了缓存。
  以前这些每 120ms 全量重做、并且每个鼠标事件都重建一次进程快照，
  主线程被拖住时整机光标都会卡顿。
* **静音**：用 WASAPI 的 `IAudioSessionManager2` 找到目标进程的音频会话，
  先**记录该会话原本的音量**（`ISimpleAudioVolume::GetMasterVolume`），再把音量降到 **0%**
  （`SetMasterVolume`）并静音（`SetMute`）——只静音对有些程序无效（实测表现为"被遮罩的程序
  还在响"），降音量更可靠。临时解锁或遮罩解除时还原原来的音量与静音状态
  （无音频设备时安静降级，并把失败原因记在 `audio.LAST_ERROR` 里方便排查）。
  这套静音曾经**一次都没生效过**，原因是两个 ctypes 层的错，都已修正：一是 `_guid()`
  解析 GUID 时漏掉第 4 段、只从第 5 段取 6 字节，于是 CLSID 与三个 IID 全是错的，
  `CoCreateInstance` 一直返回 `0x80040154`（`REGDB_E_CLASSNOTREG`）；二是
  `IMMDevice::Activate` 的**参数顺序写错**，把 `REFIID` 传成了空指针，于是会话枚举恒为 0
  却不写 `LAST_ERROR`（静默失败）。修正后还会**遍历全部活动输出端点**
  （`EnumAudioEndpoints(E_RENDER, DEVICE_STATE_ACTIVE)`，一个都取不到时才退回默认端点）：
  以前只查默认端点，声音走副输出 / 虚拟声卡时根本找不到会话；一个进程可能有多个会话，
  也全部登记。程序会把音量调回来或重建会话，所以定时同步时对已登记的会话**再压一次 0%**，
  只有新出现的会话才算新增；确实压不下去时 `audio.LAST_ERROR` 会写明
  "N 个音频会话无法降到 0%（可能被程序独占）"。
* **解除遮罩时必须把音量还回去**：这里以前有个反直觉的坑——如果会话在 Monitor 接管**之前**
  就已经是 0% + 静音（程序切场景 / 重新初始化音频会重建会话，而 Windows 是**按应用**记住音量
  的，所以新会话一出生就是 0%；上一次 Monitor 被强杀、没来得及还原也会留下这种会话），
  旧实现会把这个 0% 当成"原始音量"记下来，解除遮罩时**把 0% 写回去**，
  表现就是"限制已经结束了，程序还是没声音"。现在做了五处修正：
  ①只有**非 0% 且未静音**的会话才会被记为原始音量，0% / 读不到音量一律按
  `FALLBACK_VOLUME = 100%`、未静音回退（阈值 `SILENT_LEVEL = 0.01`）；
  ②登记结果按**程序路径**持久化到数据库（`S_AUDIO_ORIGINALS`，JSON），程序重建会话或
  Monitor 重启后仍用第一次记住的音量还原，不会被中途的 0% 顶掉；
  ③`mute(set())`（遮罩撤销但那一刻查不到运行中的进程）和 `_maintain_effects` 拿到空集合时
  也会走还原路径，不再"没有目标就什么都不做"；
  ④Monitor 启动时调用 `ProcessMuter.recover()`，把上次没来得及还回去的音量补上；
  ⑤`restore()` 里单个会话还原失败不再被直接丢弃，留在待还原集合里下次重试，并写
  `"N 个音频会话还原失败，稍后重试"`（原来音量那一步失败也会被当成成功，现在两步取与）。
* **关闭出口**：遮罩上提供「关闭程序」，确认后正常结束该程序所有进程；
  未响应时再询问是否强制结束。
  全部可见顶层窗口（排除工具窗口与托盘等系统窗口），窗口边界取 DWM 的
  `DWMWA_EXTENDED_FRAME_BOUNDS`（`GetWindowRect` 会带上不可见边框而偏出一圈）；
  枚举到的是物理像素，还要按窗口所在屏幕的 DPR 换算成 Qt 逻辑坐标，
  否则在 125% / 150% / 175% 缩放下遮罩会整体放大并偏移。
  遮罩**不设** WindowStaysOnTop，而是用 `SetWindowPos` 把它压在目标窗口正上方
  （注意 `hWndInsertAfter` 是"排在前面"的窗口，也就是被调整窗口会落到它**后面**：
  直接传目标窗口会把遮罩塞到目标**下面**，实测两个重叠窗口时遮罩被完全盖住，
  所以这里改成插到"目标正上方那个窗口"之后，目标已在同层最上面时才置顶），
  因此不会盖住其它程序。弹「临时解锁」或「关闭程序」确认框时遮罩**保持可见**
  （弹窗自身置顶显示）：以前弹窗期间会先隐藏遮罩，于是只要点一下这两个按钮、再取消，
  目标程序就能正常使用；现在遮罩只会在真正解锁后消失。
  多个窗口同时显示，临时解锁对所有窗口一起生效。
* **程序 / 网站使用限制**：规则卡片**只显示手动添加过的目标**（点击「添加程序 / 网站」
  从首页目标里勾选，弹窗里程序与网站各占一个分区、网站带地球图标），不再自动列出全部目标；
  卡片上的「删除规则」= 从控制页移除该目标（规则与计时状态一并清除），
  并播放与首页 / 日志页一致的删除动画（卡片右移淡出、其余卡片依次上移补位）。
  每张卡片可直接编辑每日上限与连续暂停阈值（数值 + 单位下拉），保存即时生效，
  底部显示今日已用 / 连续已用 / 当前状态。程序与网站使用**完全同一套**规则与状态机，
  网站只是"算不算在用"由浏览器当前标签页决定（见上一节）。
  卡片**默认收起**（以前全部展开太占地方）：标题行常显程序名 + 规则摘要
  （如"时段 22:00–07:00（周一、周三、周五）· 每日 2 小时 · 连续 45 分钟休息 5 分钟"）+ 实时状态，
  点标题行的空白处（拖动手柄 / 展开箭头 / 删除按钮除外）展开或收起，箭头同步在
  `chevron_right` / `chevron_down` 之间切换——**初始态就是未展开的 `chevron_right`**：
  以前箭头在构造时硬编码成 `chevron_down`、只有状态变化时才同步，于是默认收起的卡片
  一开始显示的是"已展开"的向下箭头；展开状态会记住——保存一张卡触发的整体重建
  不会让所有卡片一起塌回去。
  卡片左侧有**拖动手柄**（`monitor/ui/reorder.py`，与通知页、首页手动排序共用），按住手柄拖动可以调整顺序：
  **程序与网站各自一组、不能互相拖入**（拖到另一个分类的位置也只会在本组内换位），
  松手即写入数据库（`order.control.program` / `order.control.site`），重启后仍按这个顺序显示；
  拖到列表上下边缘会自动滚动，越靠边越快（距边缘 46px 内开始，每帧最多 26px、24ms 一帧），
  滚动出来的新位置继续参与排序。
  拖动过程有动效：按住手柄时卡片**轻微放大（约 1.6%）并加深阴影浮起**（130ms），
  脱离列表改为**跟随鼠标光标**移动（浮层挂在该页滚动视口上），
  原位留一个**虚线占位框**标出将要落下的位置；经过别的卡片时，那些卡片用
  140ms 缓动**让出空位**；松手后卡片用 160ms 落回占位框并写库，取消拖动则整体还原。
* **规则摘要 / 状态行过长不会溢出**：标题行的两行小字（规则摘要、实时状态）改成
  **单行省略号**（`monitor/ui/control_page.py` 的 `_ElidedLabel`），
  鼠标悬停时用 tooltip 显示**完整原文**；文案本身也做了精简
  （"每日 2 小时""连续 45 分钟 暂停 5 分钟""今日 1 小时 20 分""时段中 剩 35 分"）。
  以前规则配得越多（多个时段 + 多个星期），摘要就越长，直接把文字挤出卡片右边缘、被硬裁掉。
* **Monitor 自己不能被限制**：添加程序的列表里**不会出现 Monitor 自己**——开发运行时它的主体进程
  是解释器目录下的 `pythonw.exe`（任务管理器里看到的就是它），打包后是 `Monitor.exe`。
  `util.is_self_path()` 同时按绝对路径与解释器同目录的 `python.exe / pythonw.exe / Monitor.exe`
  判定；控制页候选列表（`ControlPage._addable_programs`）、`ControlService.save_rule`
  与 `reload()` 三处都拦截，历史遗留的自规则会在 reload 时被清掉。
  限制自己等于把自己遮罩 / 静音，之后控制页再也打不开，所以这里必须直接不给选。
* **关闭规则即重置该程序的计时状态**：把每日上限或连续暂停的开关关掉时，对应的累计
  （今日已用 / 连续累计 / 已累计休息 / 暂停截止与暂停标记）会立即清零，因为关掉规则的那段时间
  也不该继续累计、更不该在重新打开时"立刻又被遮罩"。以前关掉规则后后台计时与暂停状态都留着，
  于是出现"关掉规则计时不清零""遮罩时关掉规则、再打开又立刻被遮罩"。
* **启用控制总开关**：**关闭不需要密码**（能进这一页本身就说明刚刚验过密码，再问一次是多余
  的；用户明确要求去掉这一步），关闭后所有规则暂停生效、所有遮罩立即消失。
  打开需要 **Monitor 以管理员身份运行**——遮罩要压住以管理员身份运行的游戏、系统级静音
  也需要权限，因此非管理员点这个开关会**立刻回弹**并询问是否以管理员身份重启
  （选"是"就重启，重启后开关才可打开；已在管理员权限下运行则不受影响）。
* **退出程序要密码（总开关打开时）**：三条"用户主动退出"的路径——**托盘右键 → 退出**、
  **标题栏 ✕ 且设置里"点击关闭程序时"选的是"关闭 Monitor"**、**Alt+F4**——只要"启用控制"处于
  打开且设过密码，就先验一次密码，而且**每次都重新问**（不给"刚验证过就放行"的宽限）。
  另外两处**"以管理员身份重启"**（控制页开关、设置页「以管理员身份启动」）**只要设过密码就问**
  ——那条路径等于退出现进程再提权重启，不该成为绕过闸门的后门。
  Windows **关机 / 注销**不拦（那是系统的会话结束事件，拦下来只会挡住关机），
  `--quit-after` 这类冒烟参数、自检、以及程序内部的重启流程也都走强制通道。
* 控制事件写入日志页（"达到每日上限""被临时解锁""触发强制暂停"）。


### 通知

右栏为**通知设置**（`monitor/ui/notify_page.py` + `monitor/notify.py`）：

* **全局通知设置**（可展开）：三行事件勾选 —— 第一行"程序打开时 / 程序关闭时"、
  第二行"程序达到每日上限时 / 程序被临时解锁时"、第三行"程序触发强制暂停时"、
  第四行"程序追踪时长达到指定时长"改为**内联展开的下拉栏**：点击右侧箭头会真正把这一栏
  撑高（不是浮在容器上的弹窗），展开后每行一个时间值、右侧独立的 **−** 按钮移除该值；
  左侧 **+** 号按钮点击即展开下拉栏，并在最下方自动新增一行待选项 —— 该行是可通过微调框
  输入分钟数的输入框，确认「添加」后成为正式时间值，反复点 **+** 不会堆积出多行待选项；
  不再有勾选框、也不会撑破窗口宽度；第五行"控制页密码修改时"。
* 勾选框勾选 / 取消勾选带进度动画（`CheckBox` 用 `checkProgress` 属性驱动 √ 的缩放与淡入淡出）。
* 展开 / 收起卡片时**只收缩外层裁剪容器的高度**（内容控件在动画期间被冻结成自然高度，
  动画结束再解冻）：以前每帧都改内容控件的 min/max 高度，内部布局每帧重排、文字重新换行，
  表现出来就是"卡片收起时在发抖"。只冻结内容高度还不够，抖动还有两个来源，都已修掉：
  一是裁剪容器变矮后父布局当帧仍按旧高度排布，多出来的空间被**可伸长的标题行**吃掉，
  于是下面的内容被顶下去、下一帧又弹回来（逐帧 ±5~12px 来回跳，实测到的就是它），
  修法是在 `monitor/ui/notify_page.py:_clip_holder()` 里、当裁剪容器是布局最后一项时
  补一个尾部弹簧 `addStretch(1)` 把多余高度兜住；
  二是滚动条隐藏时 `QScrollArea` 会用视口宽度重新拉伸内容控件（实测 +9px，文字跟着重新换行），
  修法是在 `monitor/ui/controls.py:SlimScrollArea` 里给内容控件**固定宽度**
  `self.width() - self._bar_width()`（不再用 `setViewportMargins`——它在滚动条隐藏时
  不算进视口），滚动条显示/隐藏与窗口缩放时都重算。逐帧几何探针确认：收起与展开过程中
  卡片内所有文字控件的 x / y / 宽度全程恒定，只有高度在缩。
* 展开时**卡片内的文本与图标也不许被压矮**：动画的起止高度不能直接用旧宽度下算出的
  `sizeHint`——同一个控件在 100px 宽时 `sizeHint = 403`、在真实宽度（1025px）下只要 375，
  布局会在第一帧就把多出来的 28px 收回去，表现出来就是"文字行高 / 图标高度收缩"。
  现在 `anim.animate_height()` 先 `layout().activate()` + `_settle_ancestors()` 把宽度定下来，
  再用 `heightForWidth(widget.width())`（控件有 heightForWidth 时）取自然高度，
  冻结值因此与真实排版一致；通知页卡片、时长下拉栏、控制页规则卡三处共用这一条。
* 新增按钮统一使用带边框的方形 + 号样式，便于辨识。
* **独立设置**：容器标题右侧同样有 **+**，弹窗勾选要单独配置的程序；每个程序一张可展开卡片
  （卡片显示该程序自己的图标与名称），
  使用同一套事件 UI，底部为"移除此独立设置"。未被加入控制页的程序，其第三至五行置灰不可勾选。
  未单独配置的程序使用全局设置。程序从首页删除或移除独立设置后，本地都不再保存该程序的独立设置。
  卡片左侧有**拖动手柄**（与控制页、首页手动排序共用同一套排序逻辑）：程序与网站各自一组、不能互相拖入，
  顺序存 `order.notify.program` / `order.notify.site`，拖到列表上下边缘会自动滚动；
  拖起时卡片轻微放大浮起并跟随光标，原位留虚线占位框，经过的卡片让出空位。
* **通知通道**：可开关的「启用 Windows 通知」（托盘气泡）与「启用企业微信通知」
  （webhook 通道，填写企业微信机器人地址，支持发送测试通知）。通道开关与 webhook 地址取全局设置，
  这样即使某个程序有独立设置，只要全局通道开着就能收到通知。
  两个「发送」按钮各自只发送自己所属的通道（点「启用 Windows 通知」里的发送只发托盘气泡，
  不会顺带把企业微信也发一遍），未开启对应通道时给出提示。
  企业微群的正文**只发通知内容本身**，不带标题行：以前每条消息前面都顶着"Monitor 通知"一行，
  现在 `_send_wecom` 只提交 `{body}`（标题仍用于托盘气泡，以及 Windows 通知的标题）。
* **自定义通知内容**：每个通道展开的容器里都有"自定义通知内容"区，逐条事件（打开 / 关闭 /
  达到每日上限 / 被临时解锁 / 触发强制暂停 / 追踪时长达到指定时长 / 控制页密码修改时）
  一个输入框，留空表示使用默认文案。可用占位符 **`{program}`**（程序名）、
  **`{duration}`**（**本次追踪时长** HH:MM:SS，即最近一次运行记录的长度）、
  **`{time}`**（当前时间 `YYYY-MM-DD HH:MM:SS`）、
  **`{unlockTime}`**（**"程序被临时解锁时"专属**：本次临时解锁的时长，如 `10 分钟`；
  其它事件没有这个值，占位符会原样保留），
  另外 `{name}` 等价于 `{program}`、`{minutes}` 为本次追踪的分钟数；
  文案里写 `\n` 会转换成真正的换行，因此可以自己排出多行通知。
  默认文案同样会经过占位符渲染，且都以 `{time}` 加一个空行开头
  （如"程序追踪时长达到指定时长"默认值是 `{time}\n\n“{program}”已使用{duration}`，
  "程序被临时解锁时"默认值是 `{time}\n\n“{program}”被临时解锁{unlockTime}`）。
  发送时按通道与事件取对应模板渲染，因此同一条事件可以给 Windows 与企业微信写不同的话。
  自定义内容随全局通知设置一起存 SQLite（`notify.custom`），只在全局生效、不随独立设置覆盖。
* 保存事件勾选 / 独立设置时**只回写事件与时长阈值**（读当前库值再合并），
  不会用页面构建时的旧快照把通道开关覆盖回去：以前先关掉「启用 Windows 通知」、
  再随手勾一个事件，开关就会被悄悄改回开启，界面却仍显示关闭，于是"关掉了还是收到 Windows 通知"。
* 事件发生时由 `Notifier` 按"独立设置优先、否则全局"派发；时长阈值同一档只通知一次。

### 日志

* 顶栏右侧三条横杠图标 → 下拉菜单切换"按时间排序 / 按程序分类"。
* **按日期分隔**：日志按天插入日期分隔条（`2026-10-04 星期日`），不同日期一目了然。
* **按时间分类**：右上角下拉新增"按时间分类"，可选择年份、年份+月份或年月日查看指定时间的记录
  （月与日都带"全部"选项），筛选条会按现有日志动态列出可选的年月日。
* 控制类日志（达到每日上限 / 被临时解锁 / 触发强制暂停）与运行记录一同展示，
  只显示时间点与提示文字，不显示起止时间与时长。
* 横栏左侧的 **删除** 按钮可清理运行记录，流程与首页的"删除"完全一致：
  点击后横栏切换为左侧 `全选`（全部选中后出现 `取消全选`）、右侧 `取消` / `确认删除`；
  每条记录左侧出现圆形复选框，点击记录任意位置即可勾选，横栏右侧实时显示"已选择 N / M 条"；
  点 `确认删除` 弹出确认弹窗（列出所有被选中的记录、提示无法撤回），确认后从 SQLite 中
  真正删除，并同步刷新首页的时间信息。
* **滑动选中**：删除模式下**按住左键在记录上划过**，划过的行会连续套用按下时那一行的
  选中状态（按下时是"选中"就一路选中，是"取消"就一路取消），不用一行一行点；
  **往回滑会撤销**——整段选择是实时重算的，滑过头多选的行会恢复成按下鼠标之前的状态；
  **拖到列表上下边缘会自动滚动**——越靠近边缘滚得越快（距边缘 46px 内开始，每帧最多 26px、
  24ms 一帧），滚出来的新行会继续被选中，所以上千条记录也能一次拖完；
  松手即结束，滑动期间不会重建列表（避免把正在操作的行销毁）。
* 日志行的名称列**省略后同一轮补一次布局**（`_elide_name()` 里 `setFixedWidth()` 之后
  `layout.activate()`，并用 `_eliding` 挡住递归）：名称列宽度是省略后才算出来的，不补这一步时间列
  会停在"名称只有几像素宽"时的位置，首屏把 `10-10 16:` 压掉只剩 `30:00`（窗口任意一次缩放后才自愈）。
* **分页 + 底部悬浮选页框**：日志不再一次读回几千条、也不再每 2 秒整表重建（旧实现 288 条日志
  会建 2928 个控件、一次刷新 1~2 秒，内存每次刷新涨 53MB，任务管理器里能看到暴涨到 500MB）。
  现在**每页 200 条**，且只从数据库取"当前这一页"：
  * 分页规则（`monitor/ui/logs_page.py` 的纯函数 `build_pages()`）：每页 200 条；某天的日志装不进
    本页剩余空间时**整天挪到下一页**（页尾永远停在日期边界上）；某天自己就超过 200 条时
    **该页只放这一天、且全部放下**；某天超过 500 条时强制按 500 条切开。自检直接拿造出来的
    "每天多少条"验证这几条规则，不依赖真实数据分布。
  * 选页框（`class PageBar`）：`‹ 第 x / N 页 ›` **水平居中悬浮在页面底部、钉住不动**，
    背景是抓取背后像素再降采样放大的**磨砂**效果 + 半透明圆角面板 + 自绘阴影；只有一页时隐藏；
    第一页 / 最后一页时对应箭头置灰；翻页后列表滚回顶部。
     * **首屏就位**：日志页还没被布局撑开时（`QStackedWidget` 只摆放当前页，重建界面后这一页还是
       100×30）**不按错误几何摆放**，只记下"待摆放"，等页面第一次可见 / 窗口尺寸变化后再摆
       （`showEvent` + `QTimer.singleShot(0)` 兜底）——旧实现会把它摆在左上角压住「删除」按钮。
     * 磨砂底图**随移动失效并拉伸铺满面板**：底图按面板矩形拉伸绘制（抓到多少都必须铺满），
       选页框一移动就丢弃缓存重抓——旧实现把旧位置那块像素按左上角贴上去，于是只有一半磨砂。
     * **点页码直接跳**：点「第 x / N 页」就地变成数字输入框（回车 / 失焦跳转、Esc 取消、
       越界夹到首末页、非法输入不跳转），空闲时外观与原来完全一致。
  * "按程序分类"同样分页（`db.logs_for_program(limit, offset)`）但只按每页条数切，没有"整天"规则。
  * 删除模式下**"全选"只选中当前页**；已勾选的行**跨页保留**（翻页不清空），确认删除时按 id
    把选中的记录从数据库取回来（`db.logs_by_ids`）一起删。
  * **数据没变就不重建**：每拍只比对 `db.log_day_counts()` 给出的"每天多少条 + 最后结束时间"指纹，
    与屏幕上那份相同就直接返回，一个控件都不动；重建时也不再 `setParent(None)`（旧控件直接
    `deleteLater` 同样连带销毁子级，省掉一次刷新 0.28 秒），且**光标不在日志页时不挂全 app 的
    tooltip 事件过滤器**。实测 88 行的一页刷新从 432ms 降到 304ms，数据没变时连续刷新耗时 0ms、
    内存不再随刷新增长。
* 按时间排序：所有程序的混合日志，按时间倒序显示开始与关闭时间。
* 按程序分类：顶部固定横栏显示当前选中程序（图标 / 名称 / 路径）与右侧箭头，
  点击箭头展开下拉菜单（高度随程序数量增长，最高不超过窗口的 70%，超出时滚动；
  点击菜单外区域收起）；默认选中最早添加的追踪程序，没有程序时显示"无追踪程序"。
* **网站也在同一份日志里**：正在浏览被追踪的网站时会照常生成一条使用记录（切走后写结束时间），
  图标为矢量地球；"按程序分类"的下拉里程序与网站并列，网站显示域名并用地球图标区分。
* 存储：`data/monitor.db`（SQLite 单文件）
  * `programs(id, name, path, icon_path, added_time, last_run_time, tracking, visible, keep_logs, kind)`
    —— `kind = 'program' / 'site'`（网站用 `path` 存归一化后的域名规则，与程序共用这张表）
  * `logs(id, program_id, pid, start_time, end_time)`
  * `settings(key, value)`

### 设置

设置页顶部第一张卡片为 **语言 / 外观**：

* 语言：下拉选项 `中文`（默认）/ `English`；切换后**界面文案即时切换**并写入数据库
  （导航、页面标题、首页 / 日志 / 通知 / 设置、各类弹窗与提示均为中英双语，
  文案表见 `monitor/i18n.py`）。
* 外观：下拉选项 `浅色模式` / `深色模式` / `跟随系统`（默认，读取系统配色）；
  切换后即时生效并重建界面。浅色模式参考 DSH 桌面端：**左侧渐变、右侧纯色**；
  深色模式为当前默认配色（左侧靛蓝调渐变、内容区近黑）。

其余设置：

* 开机自启动：写注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`。
* **以管理员身份启动**（启动卡片第三项，需要管理员权限）：勾选后改为**登录时用计划任务拉起**
  （`schtasks /Create /SC ONLOGON /RL HIGHEST /TN Monitor /TR "…"`），于是开机后 Monitor
  直接就是管理员权限、**不弹 UAC**（区别于 `runas` 每次都要点确认）；同时删除注册表 Run 项，
  避免登录时启动两次。勾选时若当前不是管理员，会先询问是否以管理员身份重启，重启后由
  `monitor/app.py` 启动流程补建任务（因此任务被外部删掉也能自愈）。取消勾选则退回普通自启动。
  两个开关之间有**联动**：勾选「以管理员身份启动」时，如果「开机自启动」还没打开，会顺手把它
  一起打开；**已经打开就什么都不做**，也就不会再重播一遍 350ms 的果冻开启动画

  检查结束会把顺序与排序方式还原。
* **自检自身的安全闸**（新增检查）：不带 `--db`、或把目标库指向真实库 `data/monitor.db`
  时判定为"真实库冲突"并拒绝启动（自检第一步就是删库重建，绝不能落在真实库上）。
  管理与注册表相关的检查全部用桩（mock）替换 `autostart.apply` / `util.is_admin` /
  `QMessageBox.question`，**不会真的改注册表或建计划任务**。
  自检启动的示例程序（含应用商店别名的"计算器 / 记事本"）在收尾时按窗口句柄关闭：
  启动前先记录已有窗口，之后只关这次新出现的那些——用户自己先开着的记事本、计算器不会被关。
  "计算器"这类商店应用的窗口其实属于宿主 `ApplicationFrameHost.exe`（`calc.exe` 只是个
  随即退出的激活器），所以统计"示例窗口"时必须把宿主也算上（否则差集永远是空的、检查会假通过），
  而结束进程时优先杀它**那些名字属于示例程序的子进程**、不动宿主本身，
  避免连带关掉用户自己的其它商店应用窗口；收尾会一直重试到连续两次看不到新窗口
  （商店窗口要 1~2 秒才出来），失败时打印残留窗口的句柄 / PID / 窗口类。

自检使用独立数据库，不会影响正式数据。**但必须显式指定 `--db`**：`--selftest` 启动时会先
删除该数据库文件（连同 `-wal` / `-shm`）保证每轮都从干净状态开始——否则上一轮"添加程序"
写入的记录会被添加弹窗当成已存在而过滤掉，导致校验结果不稳定。正因为要删库重建，
不带 `--db`（或把目标指向真实库 `data/monitor.db`）时自检会**直接拒绝启动**并打印正确命令：
真实库只属于用户本人，绝不能被自检清空。

**独立的定向回归测试**（不需要跑完整自检时）：

```powershell
python tools/test_logs_deletion.py
```

针对日志页删除动画的收尾崩溃：重建回调必须等 Qt 的 `finished` / `timeout` 回调栈退出后再执行
（`QTimer.singleShot(0, parent, on_finished)`），并绑定到 `parent` 上下文——页面提前关闭时
待执行的重建会被一并取消。该测试用离屏 Qt 事件循环 + 临时数据库，不启动真实追踪、
音频控制或系统钩子，也不依赖 `C:\Windows\System32` 下的示例程序。

## 5. 打包与发布

在**打包机**上先装好运行依赖与 PyInstaller（`requirements.txt` 只列运行依赖，不含打包工具）：

```powershell
pip install -r requirements.txt
pip install pyinstaller
```

```bat
python build_exe.py            :: 单文件绿色版 -> dist\Monitor.exe + dist\Monitor-<版本>-win64.zip
python build_exe.py --onedir   :: 目录版（启动更快，适合放在 SSD 上长期用）
python build_exe.py --console  :: 保留控制台，排查"双击没反应"时用
```

* **不需要仓库里的 `data/`**：打包脚本只用源码自绘生成 `build/monitor.ico` 与
  `build/version_info.txt`，入口是 `main.py`、运行期钩子是 `packaging/rthook_stdio.py`，
  不引用任何运行时数据文件或图片。exe 首次启动会在自己旁边自动创建 `data/`、默认托盘图标
  与数据库（见 `config.ensure_dirs()` / `icon_extract.save_default_tray_icon()`），
  所以从 GitHub 下载的源码打包出的 exe、或 Release 里的 exe，都是**解压 / 打包即用**。

* **版本号**取自 `monitor/config.py` 的 `APP_VERSION`，同一串会写进 exe 的版本资源
  （产品名 / 文件说明 / 版权），发布 tag 用 `v` + 该串（当前 `v0.1.0`）。
* **默认非管理员启动**：生成的 exe 清单是 `asInvoker`，日常功能（追踪、限制、遮罩、
  暂停播放）都不需要提权。需要"开机自启 / 管理员启动 / 计划任务"时才右键 exe →
  **以管理员身份运行**，设置页里也有对应说明。
* **数据落在 exe 旁边**：冻结后 `config.PROJECT_ROOT` 取 exe 所在目录，而不是
  PyInstaller 每次启动都新建、退出即删的 `_MEIPASS` 临时目录；`data/`（数据库、图标缓存、
  托盘图、截图）与 exe 平级，升级只换 exe 即可。
* **打包参数**（见 `build_exe.py`）：`--collect-all comtypes` 是必须的——网站追踪依赖
  UIAutomation 的 comtypes 生成模块，漏了它"网站识别"会在打包版里静默失效；
  `--exclude-module` 剔掉 tkinter / numpy / pandas 等用不到的大件。
* **`packaging/rthook_stdio.py`** 是 PyInstaller 运行时钩子：窗口模式（`--windowed`）下
  PyInstaller 会把 `sys.stdout/stderr/stdin` 置成 `None`，任何一句 `print()` 都会抛
  `AttributeError` 把程序打断；钩子在入口最早处把三个标准流兜到 `os.devnull`。
* **冻结环境下的自检**：`Monitor.exe --selftest --db data/_selftest.db --shots data/_shots`
  可以整轮跑通（48 张截图、所有检查 PASS）。少数检查在冻结环境里会打印"跳过"而不是
  假装通过：几条**读源码**的断言（`inspect.getsource`，打包后没有 .py 文件可读）与
  **拉起 python 子进程发声**的音频检查（冻结后 `sys.executable` 就是 exe 自己）；
  进程树检查改用 `cmd /c ping` 当作那个安静的、长期存活的子进程。
* **发布流程**：`git tag v0.1.0 && git push origin v0.1.0`，然后在 GitHub 上新建 Release，
  上传 `dist\Monitor-0.1.0-win64.zip`（单文件 exe，解压即用）。


## 后台空闲开销优化

- 无限制目标时停用遮罩的 30ms / 120ms 高频定时器；控制服务仍每秒判定，进入限制后立即同步并恢复原有频率。
- 首页隐藏或窗口最小化时不刷新卡片时间，恢复显示时补刷新；导航目标数改为配置变化时更新。
- 追踪线程通过事件等待下一轮，配置变化和退出可直接唤醒；相同配置的五秒同步不再引发额外扫描。
- 控制状态保持五秒保存周期，跳过未变化状态，以单事务批量提交；失败整批回滚并重试，退出仍强制保存。

隔离功能回归：`python tools/test_idle_work.py`。仅使用临时数据库、离屏界面和模拟系统组件，
不启动真实追踪、音频控制或系统钩子，不进行实际性能采样。尚未测量 CPU、内存或耗电降幅。
